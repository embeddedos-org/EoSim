# Agent Responsibilities

Each role owns a slice of the work and does only that slice. Full briefs are in
[.ai/](./.ai/). These are responsibilities, not a required agent count — one
agent may hold several roles on a small change. Split when the roles need
genuinely different context, not by default.

One rule is structural rather than stylistic: **whoever implements does not
approve.** Review is a separate role because self-review reliably misses the
thing the implementer already believes is correct.

## Switching roles

Switch when the task changes domain, when specialist knowledge is required,
when independent review is required, or when the context has grown past what
one agent can hold accurately. Every switch runs the protocol in
[HANDOFF.md](./HANDOFF.md).

## Finding work that is not yours

You will. The rule is: **record it, do not absorb it, do not drop it.**

| What you found | Do |
| --- | --- |
| An unrelated defect | Record it in [TASKS.md](./TASKS.md). |
| A blocking defect | Stop and propose a separate task. |
| A security issue | Report it immediately. |
| A missing design decision | Return to the architect. |
| Work without an owner | Record the unowned requirement. |

Silently fixing something outside your task makes the diff unreviewable.
Silently ignoring it means nobody ever looks again. Neither is acceptable; the
note is what makes the difference.

## EoSim repository map

- `eosim/core/` owns platform models, schemas, registries, scenarios, jobs, and
  cluster behavior.
- `eosim/engine/` contains the native, Renode, QEMU, and hardware-in-the-loop
  simulation backends.
- `eosim/cli/` is the Click command-line surface; `eosim/gui/` and `eosim/api/`
  are optional user-facing surfaces.
- `eosim/integrations/` bridges external tools and the wider EmbeddedOS
  workspace. Treat subprocesses, sockets, serial devices, and workspace
  discovery as trust boundaries.
- `eosim/platforms/*/platform.yml` contains packaged platform descriptors.
  Validate descriptor changes against the packaged path, not a nonexistent
  root `platforms/` directory.
- `tests/unit/`, `tests/integration/`, `tests/functional/`,
  `tests/simulation/`, and `tests/performance/` cover distinct scopes. Add the
  narrowest regression test that demonstrates the behavior being changed.

## Local validation

Set up the Python environment with `python -m pip install -e ".[dev]"`. Run
`python -m pytest tests/unit -v --tb=short` for focused unit validation and
`python -m pytest tests/integration -v --tb=short` when a change crosses module
or command boundaries. Run `python -m ruff check eosim` for Python linting.

The Makefile uses `python3`, `pip3`, and POSIX utilities, so invoke its targets
only in an environment that provides those commands. On Windows, direct
`python -m ...` commands are the portable equivalent. Do not claim a skipped
external engine, SDK, simulator, `make`, GUI, network, or hardware check passed;
record it as unavailable with the exact reason.

## Change boundaries

Keep platform data, simulation behavior, integration adapters, and delivery
surfaces independently reviewable. Do not commit generated bytecode, build
outputs, coverage reports, downloaded firmware, credentials, device data, or
private vulnerability details. Follow [SECURITY.md](./SECURITY.md) for security
reports and [CONTRIBUTING.md](./CONTRIBUTING.md) for contribution and commit
requirements.
